# Базовые правила первого релиза

## Вопросы и принятые решения

### Квота файлов

Каждый пользователь, включая поставщика, получает максимум 100 МБ пользовательских файлов. Сервер проверяет квоту до записи файла.

### Заявки

Формы из разделов «Оборудование» и «Услуги» создают запись в базе и отправляют уведомление на e-mail и в Telegram. Конкретные адрес получателя, Telegram bot token и chat ID не хранятся в репозитории и добавляются в production-конфиг перед запуском.

### Проекты

В MVP проект принадлежит одному аккаунту. Пользователь может экспортировать проект в переносимый JSON-файл и импортировать его под другим аккаунтом. Совместное редактирование и прямой доступ нескольких пользователей не входят в этот этап.

### PDF

Переносятся все текущие пресеты «Плитка PDF». Каждый пресет входит в набор визуальной приёмки.

### Удаление файлов

Удаление работает в две стадии. Сначала asset получает статус `deleted` и исчезает из интерфейса. Через 30 дней cron физически удаляет файл только если asset не связан с активным или архивным проектом. Метаданные и audit record сохраняются.

### Публикация поставщиками

Поставщик может создать asset со scope `shared` без модерации. Его owner остаётся поставщиком; администратор может скрыть asset или изменить scope. Каждая публикация, скрытие и удаление пишутся в аудит.

## Последствия для реализации

- В `tt_projects` и файле переноса есть `schema_version` и `project_type`.
- При импорте файл проходит JSON-schema validation и создаёт новый проект нового владельца.
- При импорте нельзя принять путь к чужому файлу или произвольный server path.
- Медиа, которое не может быть перенесено как ссылка на системный asset, упаковывается в файл переноса только при соблюдении квоты импортёра.

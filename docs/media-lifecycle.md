# Жизненный цикл медиатеки

## Scope

- `system` - материалы Tile Tools, каталог, брендовые ресурсы; меняет администратор.
- `personal` - личные файлы пользователя; видит владелец и администратор.
- `shared` - общие файлы, опубликованные поставщиком или администратором; доступны всем пользователям сервиса.

## Квота

Каждому аккаунту доступно 104 857 600 байт, то есть 100 МБ. Считаются только активные personal/shared assets, владельцем которых является пользователь. Системные файлы не расходуют квоту поставщика.

Перед сохранением upload API:

1. получает размер файла;
2. проверяет, что новый итог не превышает квоту;
3. проверяет MIME, расширение и реальные размеры изображения;
4. сохраняет файл в `storage/users/{userId}/` под серверным именем;
5. создаёт metadata со статусом `processing`, затем `ready`.

## Удаление

1. Пользователь удаляет asset - он получает `deleted_at` и перестаёт быть доступен в UI.
2. Файл можно восстановить в течение 30 дней, если ещё не очищен.
3. Ежедневный cron выбирает assets с истёкшим `purge_after`.
4. Cron проверяет `tt_project_items`: если есть связь, файл не удаляется и попадает в отчёт.
5. Если связей нет, удаляются бинарный файл и превью; metadata остаётся как audit record.

## Публикация поставщиком

Поставщик выбирает «Опубликовать в общую медиатеку». API проверяет роль `supplier`, применяет его квоту и создаёт asset со scope `shared`. Модерации нет; администратор сохраняет право скрыть материал при нарушении правил.

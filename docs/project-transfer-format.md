# Формат переноса проекта

## Реализация v1

Серверные endpoint-ы находятся в `api/projects/export.php` и `api/projects/import.php`.

- Экспорт создаёт один файл `.tiletools-project.zip`.
- Внутри: `manifest.json` и личные/разрешённые общие изображения из `media/`.
- При импорте изображения получают новые идентификаторы и попадают в личное хранилище нового владельца; ссылки в payload переписываются на новые `mediaId`.
- Импорт жёстко ограничен 100 МБ, проверяет формат, размеры, SHA-256 и запрещает небезопасные пути в архиве.
- Нужна включённая PHP-расширение `ZipArchive`. Без него экспорт отдаёт JSON-манифест без бинарных файлов, а импорт честно возвращает ошибку конфигурации.

Файл нужен для скачивания проекта и импорта под другим аккаунтом. Это не дамп базы и не содержит сессий, паролей, путей к чужим файлам или секретов.

```json
{
  "format": "tile-tools-project",
  "formatVersion": 1,
  "projectType": "visualization | calculation | pdf",
  "exportedAt": "2026-09-20T12:00:00Z",
  "source": { "module": "calculator", "schemaVersion": 1 },
  "project": {},
  "references": {
    "systemTiles": ["k-2021"],
    "systemMedia": ["media-system-1"]
  },
  "portableMedia": []
}
```

## Импорт

1. Проверить format и formatVersion.
2. Проверить projectType и schemaVersion конкретного модуля.
3. Проверить размер файла и суммарный размер portableMedia до записи.
4. Перенести доступные системные ссылки по стабильному ID.
5. Создать копии личных медиа только в папке нового пользователя и только при наличии квоты.
6. Создать новый projectId и не переносить ownerUserId исходного аккаунта.
7. Записать результат в журнал импорта.

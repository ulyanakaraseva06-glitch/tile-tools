# Журнал реализации

## 2026-09-20 — инкремент 1: основа единого сервиса

- Создана серверная оболочка PHP без сборщика: общая навигация и маршруты для экранов из согласованных макетов.
- Добавлены каркасы визуализатора, калькулятора, PDF-редактора, оборудования, проектов, медиатеки, услуг и партнёрской зоны.
- Добавлен общий API избранного `api/favorites/index.php`: один пользовательский список для плитки, медиа, оборудования, проектов и услуг.
- Добавлена защищённая загрузка изображений `api/media/upload.php`: проверка сессии, CSRF, MIME через `finfo`, размера файла, роли, квоты 100 МБ и хеш SHA-256.
- Файл хранится вне MySQL. В БД сохраняются метаданные и ключ хранилища; путь задан в некоммитимом `config.php`.
- Добавлен шаблон конфигурации, запрет листинга и отдачи файлов из `storage/` веб-сервером.

## 2026-09-20 — инкремент 2: переносимые проекты

- Добавлены API создания и списка проектов, а также скачивание и импорт одного переносимого ZIP-файла.
- Пакет переносит проект, его связи и разрешённые изображения. На новом аккаунте медиа получают новые `mediaId`, поэтому не возникает доступа к папке прежнего пользователя.
- На импорте проверяются версия формата, лимит 100 МБ, SHA-256, MIME, размер, вложенность и квота получателя.
- Остаётся зависимость окружения: расширение PHP `ZipArchive` и настроенное закрытое файловое хранилище.

## 2026-09-20 — инкремент 3: каталог и защищённая выдача медиа

- Добавлен индекс системного каталога и CLI-импортёр `catalog/import_sravni_catalog.php`; он только читает `sravni-plitku/catalog/tiles.json` и по явному флагу делает отдельные копии preview-изображений.
- Добавлен endpoint `api/media/file.php`: личное изображение увидит только владелец, а системное/общее — авторизованный или анонимный пользователь по назначению scope.
- Пользовательские uploads не выдаются напрямую из папки; это предотвращает обход проверок доступа через URL файла.
- Для публикации поставщиком добавлен `tt_audit_events`: публикация общей медиа без модерации фиксируется с пользователем, размером и MIME-файла.

## 2026-09-21 — локальное окружение Laragon

- Создана чистая локальная база `tile_tools`; применены миграции `000`–`005`.
- Локальная конфигурация использует MySQL Laragon и отдельную папку PHP-сессий, чтобы авторизация и CSRF не зависели от прав на системенную temp-папку Laragon.

## 2026-09-21 — корректировка стратегии по обратной связи

- Отменено создание упрощённых копий экранов визуализатора, калькулятора и PDF-редактора.
- Три исходных приложения остаются функционально неизменными и подключаются внутрь общей оболочки.
- Добавлена воспроизводимая сборка React-приложений в `services/` без правки их исходных папок и локальный запуск PHP-оболочки вместе с оригинальным `sravni-plitku`.
- Для `sravni-plitku` добавлена интеграционная точка входа без маркетингового лендинга: сразу открывается оригинальный визуализатор. Исходный `index.php` не изменён.

## Перед подключением к окружению

1. Создать `config.php` из `config.example.php`, поместив `storage_root` за пределы web-root.
2. На чистом окружении выполнить сначала `000_users_base.sql`, затем `001_core_entities.sql` и `002_media_governance.sql` на staging. Базовый файл намеренно не создаёт тестовые учётные записи.
3. Сверить и только затем выполнить `003_extend_users_for_supplier.sql`.
4. Настроить лимиты PHP `upload_max_filesize` и `post_max_size` не выше операционного лимита в `config.php`.
5. Добавить реальные адрес e-mail и Telegram Bot API в закрытую конфигурацию. Их значения пока являются зависимостью.

## 2026-09-22 — инкремент 5: единая медиатека плитки

- Добавлен публичный read-only API общего каталога `api/catalog/tiles.php`; административное добавление материалов намеренно оставлено за границами текущего этапа.
- Добавлены API личных папок и связи папка–плитка. Серверные папки всегда ограничены текущим пользователем.
- Гостевое избранное хранится в общей PHP-сессии, поэтому оно одинаково на портах оболочки и визуализатора; после авторизации используется `tt_favorite_items`.
- Все три сервиса обращаются к одному `tile.id`. Это исключает расхождение избранного и позволяет позднее связать плитки с проектами без миграции идентификаторов.
- Изображение плитки в калькуляторе используется и как карточка выбора, и как повторяемая текстура внутри расчётных плиток. До загрузки изображения применяется каталоговый `hex`. Ранее выбранные формат, коробочные параметры и раскладка не меняются. В PDF используется то же системное превью.

## 2026-09-22 — инкремент 6: единый реестр проектов

- Общая оболочка принимает безопасные события сохранения от трёх встроенных сервисов и ведёт локальный реестр `tile_tools_projects_v1`; при активной авторизации изменения синхронизируются с `tt_projects`.
- «Посчитай плитку» и «Плитка PDF» передают свои полные рабочие снимки, а «Сравни плитку» создаёт проект после успешной JPG-выгрузки с выбранным интерьером, плиткой по зонам и настройками света.
- «Вернуться к работе» восстанавливает локальный снимок перед открытием React-сервиса; для визуализатора оболочка передаёт состояние в iframe сообщением после загрузки.
- Статусы `draft`, `active`, `done` и `archived` меняются пользователем. Серверное изменение проверяет владельца проекта и CSRF.

## 2026-09-22 — инкремент 7: услуги Vilray Studio

- Страница услуг собрана по согласованному трёхколоночному макету: навигация по категориям, карточки направлений, постоянная форма заявки и портфолио-блок.
- Состав услуг, цены и смысл описаний синхронизированы с публичной страницей Vilray Studio; текст адаптирован для интерфейса Tile Tools.
- Каждая карточка открывает подробный поп-ап и автоматически подставляет выбранную услугу.
- Обе формы используют один внутренний endpoint и записывают заявку в `tt_lead_requests`. Внешняя доставка намеренно отключена до отдельного решения по e-mail и Telegram.

## 2026-09-22 — инкремент 8: личный кабинет

- Профиль в шапке теперь строится по записи `users`, а для имени используются имя и фамилия либо локальная часть e-mail как безопасный fallback.
- История заявок ограничена `user_id` активной сессии и типом `service`, поэтому пользователь не может увидеть чужие обращения или заявки оборудования.
- Добавлены вход по существующей учётной записи, регенерация идентификатора сессии после входа и CSRF-защищённый выход.

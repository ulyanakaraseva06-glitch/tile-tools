## 1. Что это за проект

Веб-сервис-визуализатор керамической плитки для русскоязычной аудитории
(домен: `vis.vilraystudio.ru`). Пользователь выбирает плитку справа по фильтрам,
кликает по нужной, затем указывает **зону** на основной сцене (стена/пол/фартук),
куда эту плитку «положить». Сцену (ракурс комнаты) можно менять из миниатюр под
основным окном рендера. Готовый результат экспортируется в JPG.

**3D нет.** Всё делается наложением изображений и **обрезкой по SVG-маскам зон**:
базовое фото комнаты + поверх него рендер плитки, обрезанный по контуру зоны.

Есть личный кабинет, регистрация с капчей, роли (user/admin), месячный лимит
скачиваний, админ-модули (каталог плитки, аналитика) и публичный лендинг.

## 2. Технологический стек

- Фронтенд: **vanilla JS** (без фреймворков) + **SVG-маскинг** + Canvas (экспорт).
- Бэкенд: **PHP 8+** (функции PHP 8.0+ — `str_contains`, `str_starts_with`,
  `str_ends_with` и т.п. — разрешены).
- БД: **MySQL** (PDO, singleton-подключение). База `u3500136_visuserdb`, charset **utf8mb4**.
- Данные каталога: **JSON** (`catalog/tiles.json`, `catalog/filters.json`) — **не в БД**.
- Хостинг: **reg.ru shared hosting (ISPmanager)**, Apache + `.htaccess`. Нет root,
  ограниченный доступ к серверным инструментам.
- Экспорт HQ через **Python/Pillow — НЕ реализован** (в проекте нет ни одного `.py`).
  Экспорт сейчас полностью клиентский: Canvas в `export-image.js`, в нативном разрешении
  рендеров без апскейла.

**Новые технологии вводить только с явным предупреждением** (см. `SKILL.md` проекта).

## 4. Как это работает (поток данных)

1. Запрос `/` → **`index.php`**.
2. Нет сессии → редирект на `landing.php` (публичный лендинг).
3. Есть сессия → `require_login()` (проверка бан/ограничение/одобрение) →
   `ensure_month_reset()` (ленивый сброс месячного счётчика).
4. `index.php` читает `index.html` и через `str_replace` **перед** `<script src="export-image.js">`
   инъектирует:
   - `window.SP_USER` = { id, name, email, role, favorites, monthly, limit, csrf };
   - `window.SP_TILES` = `catalog/tiles.json` (+ мердж `tiles.demo.json`, если файл есть);
   - `window.SP_FILTERS` = `catalog/filters.json`;
   - `<script src="analytics/track.js">` (до `betavis.js`, чтобы был готов `window.SP_ANALYTICS`).
   Все JSON экранируются (`</`, U+2028/2029), чтобы не «разорвать» тег `<script>`.
5. **`betavis.js`**: `TILES_DB = window.SP_TILES || EMBEDDED_TILES`. `EMBEDDED_TILES` —
   аварийный демо-фолбэк внутри файла (**не мусор**), срабатывает только при открытии
   `index.html` напрямую, без PHP.
6. Рендер сцены: базовый JPG из `ROOM_ZONES[roomId].base`, поверх — рендер плитки,
   обрезанный по SVG-маске зоны (`clip-path`, opacity `0.92`).
7. Экспорт (`onExport` → `window.TileExport.generate()`): собирает то же самое на canvas.
   Гейт только один: `if (!roomData(S.roomId))` → **экспорт работает для всех 5 комнат.**
   Скачивание блокирующе проходит через `auth/api/log_download.php` (лимит + счётчик).
8. Продуктовые события — через `analytics/track.js` → `track_event.php`.

### Комнаты и рендеры

`ROOMS` / `ROOM_ZONES` в `betavis.js`, те же id — в `catalog/functions.php` и в
ключах `renders` внутри `tiles.json`:

| id | Название | Префикс файлов | Базовый рендер |
|----|----------|----------------|----------------|
| `bathroom_m` | Ванная M (**дефолтная, первая**) | `R1_` | `images/renders/r1.jpg` |
| `bathroom_xl` | Ванная XL | `R2_` | `images/renders/r2.jpg` |
| `bathroom_s` | Ванная S | `R3_` | `images/renders/r3.jpg` |
| `hall` | Зал | `R4_` | `images/renders/r4.jpg` |
| `kitchen` | Кухня-гостиная | `R5_` | `images/renders/r5.jpg` |

(`R0_` — фото самой плитки, не комната.)

**Реальный рендер vs заглушка решается ПО ПЛИТКЕ, а не по комнате.**
Условие в коде: `tile.hasRealImg && renderForRoom(tile, roomId)`. Если у конкретной плитки
нет рендера под текущий ракурс — рисуется заглушка (заливка `tile.hex` + штриховка).
«Плейсхолдерных комнат» нет. Гейт `roomHasRealRenders()` — **рудимент, всегда `true`**.

## 5. Развёртывание

### Требования на сервере
- PHP 8+ с расширениями `pdo_mysql`, `mbstring`;
- **GD (`php-gd`)** — для авто-расчёта среднего цвета по фото R0. Без GD цвет молча
  подставляется нейтральный (`#D9D5CE`), правится в форме или в `tiles.json`;
- MySQL; доступ к phpMyAdmin (для выполнения SQL);
- Apache (для `.htaccess`) или Nginx с аналогичными правилами;
- **права на запись** для веб-сервера: `catalog/tiles.json`, `catalog/filters.json`,
  `images/tiles/` (создание папок и загрузка файлов).

### Порядок установки
1. Распаковать архив в корень сайта, сохранив структуру
   (`index.php`, `betavis.js`, `landing.php`, `auth/`, `analytics/`, `catalog/`, `images/`…).
2. Скопировать `auth/config.example.php` → `auth/config.php`, вписать реальные
   `DB_NAME`/`DB_USER`/`DB_PASS`, при необходимости изменить `DEFAULT_MONTHLY_LIMIT`.
3. Выполнить SQL (phpMyAdmin → SQL) **строго по порядку**:
   1. `auth/install.sql` — таблица `users` + 2 администратора;
   2. `analytics/install.sql` — сессии, события, скачивания, заметки.
4. Сменить пароли администраторов (вход → Кабинет → Сменить пароль).
   Временный пароль указан в комментариях `auth/install.sql`.

### Проверка после загрузки
- [ ] Открывается лендинг `/landing.php`; регистрация и вход работают;
- [ ] `/index.php` закрыт от гостей (редирект на вход), админка — от обычных пользователей;
- [ ] скачивание учитывает месячный лимит;
- [ ] аналитика пишет события (Админка → Аналитика → Самопроверка);
- [ ] кабинет показывает доступ и лимиты;
- [ ] служебные файлы дают 403: `/auth/config.php`, `/auth/db.php`, `/auth/functions.php`, `*.sql`, `*.md`.

### Cron (по желанию)
Раз в месяц: `php auth/cron/reset_monthly.php` (сброс месячных счётчиков).
Без cron всё работает за счёт ленивого сброса при активности пользователя.

### Безопасность (уже в коде)
PDO + prepared statements везде; CSRF-токены на всех POST; `require_admin()` на админ-страницах;
служебные файлы и `*.sql`/`*.md`/`*.log` закрыты через `.htaccess`; IP хранится только как
SHA-256 хэш; весь вывод из БД экранируется (`htmlspecialchars`). На проде `display_errors` = Off.

### Перенос проекта на другой хостинг
Переносить **и файлы, и БД**: дамп (`mysqldump`) всех таблиц → импорт → новые доступы в
`auth/config.php`. Не забыть то, чего нет в архивах: реальный `auth/config.php`,
папку `images/tiles/`, актуальные `catalog/*.json` с сервера. Домен нигде не захардкожен
(`DOMAIN = ''` в `betavis.js`, пути относительные) — на новом домене заводится сам.
Новую БД создавать в **utf8mb4**. `.htaccess` — Apache-специфичен: на nginx нужен эквивалент.
Cron перерегистрировать.

> ⚠️ **Дамп БД несовместим с MariaDB.** Таблицы созданы с коллацией `utf8mb4_0900_ai_ci`,
> которая существует **только в MySQL 8**. При заливке в MariaDB дамп падает с
> `ERROR 1273: Unknown collation`. Если новый хостинг даёт MariaDB — предварительно заменить
> в дампе `utf8mb4_0900_ai_ci` → `utf8mb4_general_ci` (проверено, данные и кириллица не страдают).
> Это ещё одна причина фиксировать стек как **MySQL**, а не «MySQL/MariaDB».

## 6. Каталог плитки

### Архитектура данных
Раньше база плиток была **зашита в `betavis.js`**. Теперь источник истины —
**`catalog/tiles.json`**, который `index.php` внедряет как `window.SP_TILES`
(фильтры — `window.SP_FILTERS` из `catalog/filters.json`). Встроенный `EMBEDDED_TILES`
остался лишь аварийным фолбэком. Мёртвый `db.js` удалён.

### Как пользоваться
1. Кабинет/админка → **«Каталог плитки»**.
2. **+ Добавить плитку** → заполнить форму. Префиксы `R0_…R5_` добавляются автоматически
   (если префикс уже есть — повторно не добавляется).
3. Хотя бы один ракурс (R1–R5) обязателен.
4. Новые значения фильтров дописываются в `filters.json` глобально (появляются и на сайте).
   **Новый цвет** получает swatch `#CCCCCC` — поправить в `catalog/filters.json` (`color.swatches`).
5. Демо-плитки (`hasRealImg: false`) в админ-списке не показываются.

### Формат записи в `tiles.json`
```json
{
  "id": "italon-voyager-grey-60x60",
  "folder": "italon-voyager-grey-60x60",
  "name": "Керамогранит Italon Voyager Grey 60x60",
  "shortName": "Voyager Grey",
  "brand": "Italon",
  "hex": "#9E9B96",
  "hasRealImg": true,
  "color": ["серый"],
  "size": ["60x60"],
  "surface": ["матовый"],
  "design": ["бетон"],
  "tileImg": "images/tiles/italon-voyager-grey-60x60/R0_voyager.webp",
  "renders": {
    "bathroom_m": "images/tiles/italon-voyager-grey-60x60/R1_voyager.jpg",
    "kitchen":    "images/tiles/italon-voyager-grey-60x60/R5_voyager.jpg"
  },
  "attribute1": { "name": "Морозостойкость", "values": ["да"] },
  "attribute2": { "name": "Страна", "values": ["Россия"] }
}
```
Поля `color/size/surface/design` — **массивы** (несколько значений или пусто).
Ключи `renders` — **id комнат** из таблицы в разделе 4.

## 7. images/renders — почему нужны И jpg, И svg

- **`r1..r5.jpg`** — живые фоновые фотографии сцен. Грузятся в рантайме как `base` в
  `ROOM_ZONES` и как миниатюры выбора ракурса. Без них сцена не отрисуется.
- **`r1..r5.svg`** — **исходники геометрии зон** (сделаны в CorelDRAW). Из них взяты
  `viewBox` каждого ракурса и контуры зон, которые сейчас захардкожены в `ROOM_ZONES`.
  В рантайме **не подключаются**, но это единственный источник, по которому можно
  переразметить или добавить зоны. **Не лишние. Не удалять.**
  `viewBox` в SVG обязан совпадать с `viewBox` комнаты в `ROOM_ZONES`
  (пример: `r1.svg` → `260.7 × 195.52`).

## 8. Аналитика: какие данные и где

## 9. Подводные камни (обязательно учитывать)

1. **Изоляция модулей нерушима.** Лендинг (`.lp-*`, `--lp-*`) не должен протекать в
   визуализатор и другие модули, и наоборот.
2. **Cyrillic-имена файлов небезопасны.** Санитайзер вырезает кириллицу — разные файлы
   схлопываются в одно базовое имя. Всегда детерминированные имена по слоту: `<PREFIX><slug>.<ext>`.
3. **ID плитки — строки.** Числовое приведение `+dataset` на slug-ID даёт `NaN`.
   Избранное и поиск трактуют ID как строку (`favKey()` в JS, `sanitize_fav_ids()` в PHP).
4. **PHP 8+.** Функции PHP 8.0+ разрешены (прежнее ограничение 7.4 снято).
5. **Серые зоны — это тоже зоны.** Не-зона только прозрачная фигура `fill:none`.
6. **`box-shadow` обрезается** родителем с `overflow:hidden` — лечится добавлением padding,
   а не снятием overflow.
7. **Специфичность CSS для зон.** Заливки SVG-зон задаются инлайн-стилями, не классами.
8. **Паритет экспорта.** Любой эффект, добавленный в сцену (`buildBathroomScene()`),
   зеркалить в `export-image.js` с тем же blend-режимом/настройками (`TILE_OPACITY = 0.92`).
9. **`viewBox` SVG-исходника = `viewBox` комнаты** в `ROOM_ZONES` (см. раздел 7).
10. **`images/tiles/` — только на сервере**, в архивах её нет: не удалять, не тянуть в патчи.
11. **Реальный `auth/config.php` — секрет:** в архивы-поставки не кладётся, заливается отдельно.
12. **`roomHasRealRenders()` — рудимент:** всегда возвращает `true`. Логика заглушки
    пер-плиточная. Не принимать за работающий переключатель.
13. **`EMBEDDED_TILES` в `betavis.js` — не мусор**, а аварийный фолбэк при работе без PHP.
14. **`betavis.js` не обёрнут в IIFE:** все объявления (`S`, `DOMAIN`, `TILES_DB`, `ROOM_ZONES`…)
    — в глобальной области. Учитывать при любой интеграции с чужим кодом.
